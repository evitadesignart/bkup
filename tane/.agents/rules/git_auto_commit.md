# Antigravity 完全自動動作＆ Git安全運用ルール (マルチプロジェクト環境)

本ルールは、どのPC・どの環境で Antigravity を起動した場合でも、ユーザーが追加設定や手動操作を一切行わずに Antigravity 内で安全に作業を完結させるための絶対遵守命令です。

### 1. ディレクトリ限定の Git コミット＆プッシュ（絶対厳守）
このリポジトリには複数の案件フォルダが並存しています。

* git add . または git add -A などの全ディレクトリ一括ステージングは固く禁止する。
* コミット時は、必ず現在依頼されている作業対象のフォルダ（例: git add horo/ や対象ファイル）のみをピンポイントで明示指定すること。
* これにより、別PCで他案件のファイルが作業・変更されている場合でも、それらのファイルを巻き込んだり上書き・削除することを完全に防ぐ。

### 2. コミット＆プッシュの完全自動化ワークフロー
作業完了時は以下のステップを Antigravity 自らが自動で実行し、完結させること。

1. **対象フォルダのみステージング**: git add <作業中フォルダ名>/ （例: git add horo/）
2. **コミット**: git commit -m "<作業フォルダ名>: <日本語のわかりやすい変更要約>"
3. **リモート同期と安全なプッシュ**: git pull --rebase origin main で安全にリモート最新を取得後、git push origin main を自動実行。

### 3. ファイル保護と文字コード
ファイル編集・新規作成時は必ず UTF-8（BOMなし）で保存し、文字化けやファイル破損を絶対に起こさないこと。

### 4. リモート履歴の強制上書き等による同期エラー（コンフリクト）発生時の対応
サーバー側（origin/main）の履歴が強制上書きされた影響等で、git pull --rebase 時にコンフリクト（リモート側でフォルダが消失している等）が発生した場合は、以下の手順で安全に履歴を統合すること。

1. **リベースの強制停止**: コンフリクトで停止した場合は直ちに git rebase --abort を実行し、安全な状態に復帰する。
2. **マージによる履歴統合**: git merge origin/main --allow-unrelated-histories -m "Merge remote-tracking branch 'origin/main'" を実行し、サーバー側の履歴とローカルの変更をマージする。
3. **統合後のプッシュ**: マージ完了後、git push origin main を実行してリモートへ反映させる。

これにより、サーバー側の最新履歴を上書きして消去してしまう事故を防ぎつつ、現在の作業フォルダを安全に同期できる。

### 5. 自動保存（バックアップ）成功時の明確な報告と確認補助
Gitの仕組みを知らない担当者でも、「確実にサーバーにデータが保存（バックアップ）されたこと」を安心して視覚的に確認できるよう、自動プッシュ完了時には必ず以下の対応を行うこと。

* 作業完了の報告とあわせて、「サーバーへの自動保存（バックアップ）が完了しました」と明確に伝える。
* 該当リポジトリのGitHub URL（ https://github.com/evitadesignart/bkup/ ）をチャット上にクリック可能なリンクとして提示し、「こちらのリンクから、サーバー上に最新データが安全に保存されたことをブラウザから直接ご確認いただけます」と案内する。
