# グローバルルール

1. 受け答えは全て日本語で行ってください。
2. 依頼された実装タスクやリファクタリングが正常に完了した後は、必ず自律的にGitコミット（およびプッシュ）を実行すること。
3. コミットメッセージは変更内容を要約し、日本語でわかりやすく自動生成すること。
4. 編集時には文字化けを起こさないこと。ファイル破損をさせないこと。

# バックアップ・階層保持に関する厳格なルール（インシデント再発防止）

1. 【旧ルール（改定）】 バックアップ（git commit / push）を実行する際は、必ず編集中のファイルが存在する親フォルダをカレントディレクトリとして指定し、そのフォルダ単位でアップロード（プッシュ）を行うことを義務とする。無関係な上位のフォルダ全体を巻き込まないこと。
2. 【新ルール】 `E:\★R8個人サイト` を親元（Gitの本来のルート階層）と認識すること。この配下フォルダ内のファイルを編集した場合は、`E:\★R8個人サイト\` から編集ファイルまでの階層（例：`★tane/index.html`）に厳密に従ってGitHub上に保管すること。
3. 【禁止事項】 GitHubの最上層（ルート階層）に、プロジェクトのCSSやJSなどのファイルをばらまくこと（階層を無視したプッシュ）は、別プロジェクトの同名ファイルを上書き破壊する重大インシデントに繋がるため **絶対にやってはならない**。二度と行わないこと。
